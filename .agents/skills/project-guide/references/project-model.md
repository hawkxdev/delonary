# Delonary project model

This reference belongs to [project-guide](../SKILL.md). It describes the intended model at the design stage; it does not establish runtime behavior or replace an assigned feature's acceptance criteria.

## Project resources and work

A project resource is a location of relevant material: source repository, project directory, notes, documents or correspondence. External links can provide navigation without importing the material itself. A task represents work with a next action or deadline and is intended to be managed inside Delonary. A resource link alone does not complete an operational task.

Client communication remains in its existing channels. Relating correspondence and recording agreements do not imply an automatic inbox, message import or permission to send a message. Client login and a customer portal are outside the selected initial scope.

## Resource measurements and project economics

The intended cost inputs include owner time, agent time, weighted token usage and additional attributable expenses. Automatic intake must retain source identity, project attribution, units, covered period and coverage limits. Missing measurements remain unknown; a partial cost total cannot establish complete project profit.

Contract value, invoiced amount, received payment, accepted-work revenue, resource cost and profit represent different facts. ERPNext's native project margin must be compared with the required cost model before reuse. A matching field name does not establish matching accounting semantics.

## Template documents

The intended action generates a document from a selected template and project data inside the system, with both DOCX and PDF as outputs. Attaching a link to a separately produced file does not fulfill that action. A verification scenario needs synthetic inputs, field substitution checks and inspection of both resulting formats. The template engine and conversion route remain undecided.

## Agent operations

AI agents need MCP access that includes writes. Coverage must be established for each required entity and custom action using the actual installation's permissions and persisted results. Tool discovery, an endpoint response or a successful read does not establish write coverage. No installed Delonary MCP server is claimed.

## Foundation and extension questions

ERPNext supplies the selected application foundation; Frappe supplies its application framework. A separate custom Frappe application is the proposed place for adaptations. Exact releases, application packaging, deployment, input connectors and upgrade behavior still require technical decisions and verification.

Useful trial scenarios are: a project resource can be found from its project; a task retains its next action; measurements reach the correct project with explicit coverage; a template produces both formats; an authorized agent action persists; and an upgrade preserves the extension. These are proposed checks, not completed tests or an assigned implementation plan.
