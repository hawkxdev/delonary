# Contributing to Delonary

Delonary is in design. Discuss a proposed change with the project owner before implementation so that it addresses an agreed scenario and does not assume an installed ERPNext environment.

Describe the problem, expected outcome, current workaround, acceptance criteria and any affected project concepts. Distinguish a desired feature from demonstrated behavior. Use synthetic examples and omit credentials, customer records and private attachments.

Read [AGENTS.md](AGENTS.md) for structure, verification and change authority, and the [project model](.agents/skills/project-guide/references/project-model.md) for terminology. A documentation change needs complete file review, working relative links and whitespace checks. Product changes will need checks selected for their actual implementation.

Present the prepared patch and verification evidence to the owner. Commit approval, review acceptance and publication are separate decisions. If an authorized GitHub contribution route is established, use a pull request and leave the final merge to the owner.

Licensing and a public support or security-reporting channel are not established. Do not send sensitive reports through ordinary issue templates. Resolve a suitable reporting route with the owner before sharing sensitive details.
